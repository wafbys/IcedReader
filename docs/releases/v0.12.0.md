# IcedReader 0.12.0

发布日期：2026-09-17

修复版：**读客／多看格式 EPUB 的书内词注（脚注）现在会展开**——这类书的注文此前在阅读器里完全看不到。0.11.0 之后无其他改动。

## 修复

- **读客／多看 EPUB 的词注不显示**（用户 2026-09-17 报告：《真实案件才更瘆人》无法显示标注）。这类书（calibre + 多看排版，读客等出版社的爱用格式）把注写成两处：正文里一枚 11px 的圆形「注」小图标（`<a href="#footnote-N"><img zy-footnote="…"></a>`），注文则放在章末 `<aside epub:type="footnote" id="footnote-N">` 里。
  - 排版层原先只认微信读书那套 `data-wr-footernote` 空 span，于是这本书的注**既不悬停、也没有序号**——正文里只剩一枚比正文还小的小图标，读者看不出那是一段注，更读不到内容。以《真实案件才更瘆人》第 1 章为例，全章 5 处注（正文 16 章共一百多处）都是这种状态。
  - 现在两套写法走**同一套渲染**：注文取自 `<aside>`（图标自带的那份只作兜底——有的导出会把它截断），标记落在图标原位（图标换成 CSS 画的 `[N]` 上标，正文不加字），**悬停读全文、点击跳到段后注文块、`[N]` 跳回原句**都与微信读书类 EPUB 一致；章末那份 `<aside>` 原文不再重复出现在正文后面。
  - 编号规则不变：`[N]` 按段计数、回跳锚点全书唯一；标记仍是无文本 `<a>`，划线锚定的「每次渲染确定性」性质不受影响。
  - 两条兜底：注文两处都取不到时**保持原样**，不产生点不开的死标记；非 footnote 的 `<aside>`（侧栏）原地不动；不在 noteref 链接里的 `zy-footnote` 图标也保持原样。
  - 微信读书类 EPUB（《资治通鉴全本注译》等）行为一字未变。

## 验证

- `cargo test` 四个 crate 全绿（core 49 / epub 33 / pdf 17 / iced-reader 55），`npx tsc --noEmit` 无输出。词注新增 9 项单测；`iced-reader-epub` 的 `user_epubs_if_present` 增加《真实案件才更瘆人》的回归断言（图标与 `<aside>` 清空、标记带注文、注块 id 正确、章节正文不丢）。
- 桌面窗口实测（`scripts/ui-probe.ps1` 驱动绿色版）：第 1 章正文出现上标 `[1]`，段后灰字注文（「New Scotland Yard，伦敦警察厅的代称。——笔者注」「autrefois acquit，法律辩护的一种…」），章节正文与分页无变化。

## 下载与运行

分发文件：`IcedReader-0.12.0-windows-x64.exe`（18,247,680 字节，SHA-256 `C7E67FD4187C7E004ACADF21E13CB13DF92047BE27E5BCDB7D3C88321FE2FB77`，对应源码 commit `5ea914a`）

拷贝到任意可写目录即可运行：书籍、进度、划线、字体、设置与 WebView 缓存都写在 exe 同级的 `data/` 下，拷走整个程序目录即带走全部状态。系统需 WebView2（Windows 11 自带）。

要求：Windows 10/11 x64。
