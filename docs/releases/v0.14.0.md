# IcedReader 0.14.0

发布日期：2026-09-21

功能版：**对话框变成真 modal，书籍大小到处看得见**——编辑元数据与同书对照不再是自己画在背景上的一层遮罩，而是浏览器层面的模态对话框；书籍文件大小进了书架悬停、编辑元数据面板和同书对照的结论行；编辑元数据面板加宽，被裁掉的文本悬停能看全。

## 修复

- **两个对话框此前不是真 modal。** 它们是「一层 `position: fixed` 遮罩 + 一张卡片」：画面上盖住了，但底下的书架照样 Tab 得进去、点得到，`App.tsx` 里 capture 阶段的全局键还会把 ←/→/PageDown 送给对话框后面的正文去翻页，Esc 会去退全屏，读屏也能读到底下那层。现在面板本体就是原生 `<dialog>` + `showModal()`（`ui/src/modal.ts`，两个面板共用）：
  - 进 **top layer** 绘制（盖住顶栏，不受 z-index 影响）；背景整层 **inert**——点不到、Tab 进不去、读屏读不到；焦点圈在面板内，关闭后还给打开它的那个控件。
  - Esc 走 dialog 自己的 `cancel` 事件，所以「保存中不能关」这条判断仍然有效；遮罩改为 `::backdrop`，`.meta-overlay` / `.cmp-overlay` 两层 div 删除。
  - 壳层全局快捷键遇到打开的对话框直接让位（`App.tsx` 里见 `dialog[open]` 即返回），正文不再在对话框后面翻页。
  - **点遮罩不关**（0.14.0 起）：背景既然是 inert，点在它上面语义上就该是「什么也没发生」；何况编辑元数据里可能正有没保存的输入，手一滑点到旁边就丢不合适。关闭只走 Esc 与面板自己的「关闭」/「取消」这两个按钮。这条是开发中真窗口实测后改的（此前点遮罩会关闭）。
  - 编辑元数据的主书名输入框仍然在表单读完（异步）之后落焦——原来靠 `autoFocus`，改成内容就绪后显式 focus 一次，行为不变。

## 新增

- **书籍文件大小**（`list_library` 新增 `sizeBytes`，一次 stat；书架热路径其余不动）：
  - 书架：悬停**封面**或书名，提示第二行给「大小 12.3 MB」。
  - 编辑元数据面板：头部文件名旁常显，悬停给精确字节数。
  - 同书对照：「倾向保留 X」一行直接给出被点名那本的大小——同名两版常常只差在体积，这正是「为什么留它」的背景数字（列头原本就有大小）。
  - 三处共用 `ui/src/format.ts` 的 `fmtBytes`（GB / MB / KB / B；取不到显示 `—`，不假装 0 字节）。
- **编辑元数据面板加宽**：500px → 760px。
- **被裁掉的文本，鼠标一停就能看全**：八个输入框按 `scrollWidth > clientWidth` 判断是否真被裁掉（短值不弹多余提示，值改短后离开即清）；头部文件名过长时先省略号、文件大小始终可见。只读框与拼接预览原本就有 title。

## 验证

- `cargo test -p iced-reader` 70 项全绿（本版唯一的 Rust 改动是 `LibraryEntry.sizeBytes`，落在 library 的列表测试路径上）；`npx tsc --noEmit` 无输出；`npm run tauri -- build --no-bundle` 通过（vite 55 modules）。
- 真窗口核对：**「点遮罩关闭」这条已由实测发现并改掉**（见上）。焦点圈定、背景不可点不可 Tab、三处 tooltip 的逐项核对仍以桌面为准——tooltip 是系统原生提示，截图里看不到，只能人眼悬停确认。

## 下载与运行

分发文件：`IcedReader-0.14.0-windows-x64.exe`（SHA-256 见下方补记）

拷贝到任意可写目录即可运行：书籍、进度、划线、字体、设置与 WebView 缓存都写在 exe 同级的 `data/` 下，拷走整个程序目录即带走全部状态。系统需 WebView2（Windows 11 自带）。

要求：Windows 10/11 x64。
