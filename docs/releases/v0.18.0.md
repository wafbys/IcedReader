# IcedReader 0.18.0

发布日期：2026-10-14

一句话：**旧代分析缓存会被识别并自动重算**——书架自己补算，升级后不必逐本打开，「同书」提示重新可靠，阅读器的全书% 也不会再拿错章节权重；顺带，同书对照的列标题悬停能看到实际文件名。

## 修复

- **改了章节口径却没有作废旧分析缓存**：0.17.0 让「目录锚点当章」的 EPUB 补回第一个目录条目之前的前置页（封面/扉页/前言），这本书的章节列表从 193 段变 200 段，但缓存的版本号没有跟着升——旧条目仍被当作有效，它的**指纹**（同书分组的依据）、**标题序列**、**章节权重**全都留在旧口径上。《语文素养高级读本》的两份（一本是带 `(1)` 后缀的修订版：引号写法与脚注编号被改写、目录条目带锚点）因此不在书架互认「同书」，阅读器还会拿 193 段的权重去算 200 段的书（全书% 越到后面越错）。
  - 分析缓存代数 `ANALYSIS_KIND` 3 → 4、章节权重口径 `CHAPTER_CHARS_PER_SPINE` 1 → 2（`REFERENCED_IMAGE_KIND` 保持 3：它是角标的**特性**水位，旧代缓存照旧按老读法评角标，不移动任何已有角标）；
  - 书架只在指纹属于**当前代数 + 当前文件修订**时才用它分组，旧代静默跳过——宁可暂时不提示，也不给错的暗示；
  - 阅读器与 `chapter_weights` 走同一条取权重规则：只接受与当前 spine 同代、同修订的数组，否则先给空（前端按既有机制轮询），后台重算写完再取，不会出现「拿旧权重按新目录算」的中间态。

## 改进

- **书架后台自愈**：进入书架时，陈旧条目（没算过 / 文件换过 / 旧代缓存 / EPUB 缺当前权重）的前 8 本会被丢去后台重算；进书架 4 秒后自动重列一次。升级后**不必逐本打开**：打开应用、等几秒，新的「同书」提示与角标自己出现（大书库按每次 8 本逐批补上）。书架本身仍然只读缓存，重算在后台线程里，不在列表路径上。
- **同书对照的列标题悬停提示**：给「完整书名 + 实际文件名」两行。列标题长了会被省略号截掉，而同名两本真正能区分身份的是文件名（`….epub` 与 `… (1).epub`）。

## 验证

- `cargo test --workspace`：iced-reader 72（+3 ignored）/ core 65 / epub 34（+2 ignored）/ pdf 17（+3 ignored），全绿。新增单测：`weights_only_for_the_current_revision_and_generation`、`stale_generation_fingerprint_does_not_group`、`needs_reanalysis_covers_every_stale_case`、`stale_entries_are_picked_for_background_analysis`。
- `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings` 零告警；`npx tsc --noEmit`、`npm run check:ui`（两条自检）通过。
- 真书验证（按当前口径重新分析用户书库 + 直接调书架自己的分组函数）：两份《语文素养高级读本》标题序列 182 条逐条相等、总字数 460456 vs 459898（差 0.12%）、指纹不同（`8805…` vs `fc57…`）→ 互认「同书」；被挡掉的旧缓存正是 `a6de…` / 175 条 / 193 段那一份。
- 备注：真窗口的人工观感（悬停提示、书架自愈的时序）本轮未做，改动只在 Rust 单测与前端类型/自检层面验证。

## 运行环境

Windows 10/11 x64。绿色便携：书库 / 进度 / 字体 / 窗口设置都在 exe 同级 `data/`，整个目录拷走即带走状态；不要装进 Program Files；系统需 WebView2（Windows 11 自带）。
