# IcedReader 0.21.0

发布日期：2026-11-02

一句话：**标准 EPUB3 脚注终于能打开/跳转，PDF 首开与滚动不再卡顿**——扫描页按原生分辨率栅格化，预取翻倍，协议 handler 搬离 WebView2 UI 线程。

## 修复

- **标准 EPUB3 脚注可展开、可跳转**：pandoc 类 EPUB 用 `epub:type="noteref"` 锚点 + 文件末尾的 `<aside epub:type="footnote">`。按 TOC 锚点切章后注文不在当前切片里，点注号没有任何反应。现在这种标准形态接进现有词注流程：注文随标记走，悬停可读、点击跳到注文、注文里的 `[N]` 可返回正文；源文件的 `1.` 编号前缀与「返回正文」链接不再重复。《追忆似水年华（全7卷）》实测 4,337 条注全部展开。
- **PDF 首次打开卡顿**：wry 在 WebView2 的 UI 线程上同步调用自定义协议 handler，一页冷渲染 80–150 ms 会直接冻住窗口；首开连续渲染第 1/2/3 页就是那次卡顿。改为 `register_asynchronous_uri_scheme_protocol`，请求交给工作线程，渲染完再 respond。

## 改进

- **扫描页按原生分辨率栅格化**：扫描页内嵌图通常为 1762×2688，页面框只有 595×908 pt；请求 2400 px 时只是把位图放大 1.36×。现在只对「单张整页图 + 无可见文字/矢量路径」的页面封顶到图片自身像素宽（`PdfDoc::scan_native_width`），文本页、图文混排页原样不封。
- **PDF 预取改为 2 个 worker**：同一本 468 页扫描书，冷页约 128→116 ms；快速滚动从连续 4 个冷页降到约 1 个，其余全部缓存命中。
- `ANALYSIS_KIND` 5 → 6：标准 EPUB3 注文现在进入切片，章节权重需要在后台重算一次；升级后首次打开相关书籍会自动补算。
- 本版**不升级组件**：Tauri / wry / hayro / 前端依赖保持 0.20.0 时锁定的版本。hayro 0.8 与 Tauri 2.12 的升级单独立项，避免和本轮行为修复混在一起。

## 验证

- `cargo test -p iced-reader-core -p iced-reader-epub -p iced-reader-pdf -p iced-reader`：core 77（+3 ignored）/ iced-reader 69 / epub 38（+2 ignored）/ pdf 19（+3 ignored），共 203 通过。
- `cargo fmt --all -- --check` 通过；`npm run build`（`tsc && vite build`）通过。
- 新增单测：标准 noteref 展开、TOC 切片后注文仍在、非脚注 noteref 保持原样、扫描页原生宽度封顶 / 文本页不封顶。
- 真书核对：《追忆似水年华》注标可打开/跳转；《面对面的杀戮》首次打开不再卡顿；EPUB 资源加载正常。

## 运行环境

Windows 10/11 x64。绿色便携：书库 / 进度 / 字体 / 窗口设置都在 exe 同级 `data/`，整个目录拷走即带走状态；不要装进 Program Files；系统需 WebView2（Windows 11 自带）。
