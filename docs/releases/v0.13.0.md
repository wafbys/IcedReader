# IcedReader 0.13.0

发布日期：2026-09-20

功能版：**书架的「同书」提示变成一张对照面板**——同一本书在库里有多份时，先判清两版是什么关系，再逐轴并排列出可复核的数字并分别判优劣，最后给出「倾向保留哪一本」。书的 优/良/中 仍是**每本各评各的**，本版没有动这套标准，只是把两处把数字量错的地方修了。

## 新增

- **同书对照面板**（书架 → 卡片上的「同书 · 另有 N 本」）。在此之前，两本同书的差异只有悬停角标时的一句相对文案，且**不指名**说的是哪一本、也不给数字，用户无法复核，更没法据此决定留哪本。
  - **先判关系，再谈优劣**：同一排版源的两次打包／同书异版（回目一致但正文有差异）／完整版与删节（回目是子集）／同一套书的不同分卷／对不上（不是同一本，或分组误判）。不同关系该看的轴完全不同——把「同源重打包」当异版比，会把打包噪声当成「正文有差」。
  - **逐轴并排**，分四组：正文内容（是否逐字一致、乱码、缺字占位）、书内装置（词注/注文、正文插图）、打包（包内残留图、封面图、文件体积）、溯源（标识符、作者）。每轴独立判 `胜／平／并列／不可比`，**不给加权总分**——有倾向时会把支撑它的轴逐个点名，供人复核。
  - **接近算平局**：46 张与 44 张插图不再读成「谁更好」，差在容差内就标平。**平局也显示**，不静默吞掉。
  - **封面大小只呈现、不判优劣**：一套封面印成 915 KB 还是 4.4 MB 是打包选择，不是长短处。真正判负的是**包内没人引用的残留图**（换掉的旧封面、推广图）。
  - **结论文案只描述，不建议删**：面板里没有删除入口，删哪本仍走书架三点菜单的确认流程。
- 书架的「同书 ×N」改为「**同书 · 另有 N 本**」。旧写法里的 N 是「别人」的个数（两本同书各显示 ×1），容易被读成「有 1 册副本」，新文案把「不含自己」写明。

## 修复

- **EPUB 的 XML 声明被当成正文**。`scan_html` 遇到 `<?xml … ?>` 时把整条处理指令原样算进了正文：字数虚高，更要紧的是**逐字一致的两本书指纹不同**——于是「同一排版源」这条最强的判同书依据失效，两本只能靠「回目一致 + 字数 ±2%」这条弱兜底才归到一起。实测两本《王立群读史记套装》：修复前指纹 `41ed17ee…` / `06dd40c6…`、字数 1533552 / 1530267，修复后指纹与字数**完全相同**（`351e08b0…` / 1522383）。
- **「插图」数的是包内所有图**。封面、以及打包时留下的、没有任何文档引用的图，都被当成「像样的插图」在加分。同一对范本里，角标理由那句「较大插图 46 张」拆开是 **39 张真插图 + 1 张在用封面 + 6 张残留图**——一成半不是内容，却撑着它拿到了「优」。现在只数**正文真正引用到的图**。
  - 旧缓存不迁移：`analysis_kind` 小于 3 的条目仍按老口径评分，所以升级后**书架上一枚角标都不会变**，书下次打开时自动切到新口径。
- **同书之间的相对结论不再混进单本评价**。此前「同书另本插图更多」这类句子被并进这本书自己的「依据」里——库里同书一变，它的依据就跟着变，那就不再是这本书的属性。相对结论现在只出现在对照面板。
- 对照面板里的 `.ghost` 按钮沿用了暗色顶栏的近白字，压在浅色面板上（对比度约 1.1:1）字看不清；与仓库里其它浅色卡片同一处理。

## 验证

- `cargo test -p iced-reader` 70 项全绿（含 `book_compare` 9 项与 `book_signals` 的插图口径回归），`cargo check` 无警告，`npx tsc --noEmit` 无输出，`npx vite build` 通过。
- **真书实测**（两本《王立群读史记套装》，`cargo test -p iced-reader --lib -- --ignored --nocapture real_pairs`）：判为「同一排版源的两次打包」；正文与装置**全部打平**；唯一判优轴是包内残留图（4 张 · 993 KB 对 6 张 · 2.6 MB），倾向保留干净的那本；封面差 4.3 MB 只呈现、不判优；逐章条带 219 格全绿。
- 对照面板已在真实桌面上打开确认可正常显示。**逐项视觉核对尚未做**（本机开发会话里跨进程窗口枚举被限制，`scripts/ui-probe.ps1` 取不到窗口），核对清单见 `docs/ideas/book-compare.md` §9。

## 下载与运行

分发文件：`IcedReader-0.13.0-windows-x64.exe`（18,430,464 字节，SHA-256 `02F735145E8CD0760C74E95CA4B61A9C207AA10D6ABCB59769F171F179A6CCAB`，对应源码 commit `e4743ef`）

拷贝到任意可写目录即可运行：书籍、进度、划线、字体、设置与 WebView 缓存都写在 exe 同级的 `data/` 下，拷走整个程序目录即带走全部状态。系统需 WebView2（Windows 11 自带）。

要求：Windows 10/11 x64。
