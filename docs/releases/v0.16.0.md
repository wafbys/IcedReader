# IcedReader 0.16.0

发布日期：2026-09-30

一句话：**一本书只剩一个伴生 md，划线与元数据住在一起**——`data/library/<文件名>.md`（`三体.epub.md` / `三体.pdf.md`）顶部是元数据块、其下是划线档案，再往下是你自己的笔记区；`annotations.json` 退役，划线随书走（删书一起进回收站）。同时去掉「手填显示名」：书架显示的名字与库内文件名，永远是同一个拼接结果。

## 破坏性变更

- **旧文件一律当不存在**：`<书名>.md`、`<书名>.notes.md`、`data/annotations.json` 不再读、不迁移、也不删。划线要重新划、元数据要重新填（2026-09-30 拍板：可删库重来）。
- **一件伴生文件**：`data/library/<文件名>.md`。**扩展名是身份的一部分**——同名 `三体.epub` 与 `三体.pdf` 各有各的 md，不再互撞；改元数据改名时它与书文件一起改名（不再重建），删书时一起进回收站。
- **去掉手填显示名**：面板不再有「显示名」输入框与「自动填充」按钮。名字永远是 `书名 _ 副标题 - 卷册 - 作者 - 译者 译 - 年份 - 出版社 - ISBN` 的拼接结果（译者自动补结尾「译」）。想保留原文书名就写进主书名/副标题的括号里，例：`性政治 (Sexual Politics)`。「拼接预览」下面原来单独印一遍生效名的「保存后书架与文件名都用这个名字」整块也一并删除——没有第二个名字之后它必然与预览恒等（改名后果的说明并进了预览框），不再重复印同一个字符串。

## 改进

- **划线档案自带坐标**：每条划线的机器字段（`href` / `startText` / `startOffset` / `endText` / `endOffset`、颜色、位置 `posPct`、时间、摘录 `text` 与段落切点 `paras`）都写进它自己的注释块，紧跟其后是给人读的摘抄行：**一段一条 `> ` 引用**，末条是 `> （全书 N% · 划于 …）`。高亮不再依赖 `annotations.json`，重排/翻章/重启后照样贴回原句。
- **摘抄保留段落**：多段摘抄在 md 里不再是折成一行的长句。机器块用 `paras` 记下段落切点（指向 `text` 里段落之间那个空格），摘抄行据此摊成一条一段；位置回填、改备注这类整条重写之后，段落结构照样从记录重建（不是「写一次就别动」，md 的摘录与机器字段不会各自漂移）。删除时有备注的划线**每条引用都加删除线**、末条附「已删于 …」。
- **两侧互不打扰**：改元数据只重写元数据块，划线写入只动划线块与它自己那条摘抄行——文件头散文、用户笔记区、别的块逐字保留（`split_meta` / `join_meta`）；删掉一条划线也不再把整份档案删掉。
- **删书 / 改名联动**：删书把书文件与伴生 md 一起送系统回收站（可还原）；改元数据改名后伴生 md 随书更名，进度、划线、质量缓存跟着迁，你写的笔记一个字不丢。

## 修复

- **位置回填吃掉笔记空白**：首开新书时权重未就绪的划线（`pos: null`），在权重到齐后回填 `posPct` 与摘抄行的「全书 N%」时，此前会把整条记录连同笔记区一起重写，而读回来的笔记是 `trim()` 过的副本 —— 用户笔记的行首缩进、行尾空格会被悄悄去掉。现在只重写保护区与摘抄行（`notes::update_pos`），笔记区逐字保留。
- **位置回填静默失效**：`set_annotation_pos` 声明了前端根本没有发送的 `bookId`，Tauri 判定为缺失必填参而整次调用失败（`command … missing required key …`），前端又把错误吞掉 —— 首次开书那批划线的位置一直没落盘。现在命令参数与前端一致，回填真正生效。
- **长摘抄的中间不再丢失**：摘录此前被当作「重新锚定用的指纹」保存——超过 160 字就只存「头 80 + … + 尾 80」，而重锚定探针其实只读它的头尾各 24 字。于是长摘抄写进伴生 md 时，中段整段消失；md 里那句摘抄行因为带着 `…` 看起来仍像一段完整引用，很容易被当成引对了。现在摘录存**整段选区**（空白折成单行——md 的 `text:` 字段必须是单行），重锚定照旧只读头尾，md 里因此拿到完整摘抄。注意：**已经划好的旧摘抄不会自动补全**（那段文字当初就没进 md），重划一次即可。
- **新建划线的章归属**：一条新划线只经一处创建路径（`write_highlight_entry`），归到 `## 第 N 章 · 标题（N/M）` 之下；此前分两步写、第二步按「已在档案里」走原位替换，导致新划线落在没有章标题的位置上。
- **「有备注删除先确认」此前是空转**：划线删除用的是 `window.confirm`，而它在 WebView2 里既不弹框也不阻塞、直接返回真值 —— 带备注的划线于是不声不响就删掉了（备注靠留痕保住，但确认这一步等于没有；「从书库删除」用的是插件原生对话框，所以那个一直是好的）。现在改用同一套原生对话框（`@tauri-apps/plugin-dialog` 的 `ask`）：标题「删除划线」、按钮「删除 / 取消」。

## 验证

- `cargo test --workspace`：iced-reader 68（+3 ignored）/ core 64 / epub 33（+2 ignored）/ pdf 17（+3 ignored），全绿、零失败。
- `cargo clippy --workspace --all-targets -- -D warnings` 零警告；`npx tsc --noEmit` 通过；`npm run check:ui` 两条自检通过（PDF 分页/栅格宽度 + 划线摘录：整段选区不截断、段落换行保留、跨段折行、500 字不截断、中段不丢、不合成省略号）。
- 新增/改写的单测：`set_pos_leaves_the_user_note_byte_for_byte`（换回 `upsert` 写回即红）、`split_excerpt_folds_to_one_line_and_keeps_the_cuts`、`excerpt_paragraphs_tolerates_broken_cuts`、`multi_paragraph_excerpt_roundtrips_and_survives_a_rewrite`、`deletion_ledger_survives_a_read_back`、`metadata_rewrite_preserves_the_notes_body`、`split_meta_keeps_the_body_verbatim`、`join_meta_leaves_the_body_alone`、`stored_highlights_roundtrip`、`numbered_stem_copies_are_read_as_one_book`。
- 桌面窗口实测已过（真键鼠驱动真实窗口 + 逐项对盘核对）：新划线按章归组并即写入伴生 md；重启后高亮仍贴原句（此时 `data/` 里已无 `annotations.json`）；备注落进用户区且行首缩进逐字保留；把 md 里的 `posPct:` 手工清空后重开，位置被回填、摘抄行重写而用户区一个字节不动（这条同时证明 `set_annotation_pos` 真的在执行）；**多段摘抄**写成一段一条 `> ` 引用（实测一条 5 段选区 = 5 条 + 1 条位置行，块里 `paras: 45,428,605,704`），再清空 `posPct` 重开，位置回填、**段落结构原样重建**；改元数据后 epub 与伴生 md 一起更名，元数据块与新划线块同住一个文件、`originalTitle` 定格、此前写的备注完好；删书后书文件与伴生 md 都在系统回收站且原始位置正确（已实测还原回来）；从「划线」列表删除一条**有备注**的多段划线：6/6 条引用都加删除线、末条附「已删于 …」、备注与 `paras` 保留、档案文件不被删、重开不再画出该高亮。
- 「删除划线」的确认框（`window.confirm` → 原生 `ask`）同样实测过：从「划线」列表点 ✕ 先弹原生对话框（标题「删除划线」，按钮「删除 / 取消」），点「删除」才真正删除（列表行消失、档案按上面的留痕规则写）。旧行为也是实测确认的：两条删除路径（正文工具条 / 划线列表）都在带备注的情况下**不弹任何框**就删掉了。

## 运行环境

Windows 10/11 x64。绿色便携：书库 / 进度 / 字体 / 窗口设置都在 exe 同级 `data/`，整个目录拷走即带走状态；不要装进 Program Files；系统需 WebView2（Windows 11 自带）。
