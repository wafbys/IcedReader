# 想法：独立评价 + 同书对照面板

状态：**四步全部实现**（测量层 → 相对文案移出独立评价 → 插图口径改正 → `compare_books` → 书架对照面板，见 §7）。
面板尚未在真实窗口里跑过人工核对（见 §9）。
定位：**每本书独立评价自身指标**（保留现有 优/良/中 与依据），**命中同书时再叠加一层对照**，供使用者决定保留哪一本。

范本：开发书库里的两本《王立群读史记套装》（`target/debug/data/library/`），
两本角标都是 **优**、各自显示「同书 · 另有 1 本」，而现有对照输出**为空**——功能缺口在这一对书上是完全暴露的。

相关：`docs/ideas/epub-stable-id.md`（指纹与质量分的来源）、`docs/releases/v0.10.0.md`（同书异版对比口径）。

## 0. 「同书 · 另有 N 本」是什么意思

**N = 库里另有几本与本书同书，不含自己。**

`LibraryEntry.duplicates`（`src-tauri/src/library.rs`）装的是「别人」的文件名：分组后对每本 i 收集
`idxs.iter().filter(|j| *j != i)`。所以库里 2 本同书 → 各显示「另有 1 本」；3 本 → 各显示「另有 2 本」。
它是**副本数 − 1**，不是「共 N 本」。旧文案 `同书 ×1` 会被读成「有 1 册副本」，已改。

## 1. 定位：两层，互不替代

| 层 | 回答的问题 | 输入 | 现状 |
| --- | --- | --- | --- |
| **独立评价** | 这本书**自己**好不好？ | 本书的 `BookSignals` | 已有：优/良/中 + `quality_plus/minus` 依据 + 未读排序 |
| **同书对照** | 这几本里**留哪一本**？ | 同书各本的 `BookSignals` | **缺**：只有一句相对文案，且只在本角标悬浮里 |

三条边界（本次不动）：

1. **评级定义不变**：优/良/中 仍按「无缺陷 + 长处档数」判，仍然是**单本独立**算出来的。
2. **对照结论不写回角标**：比较面板看完就完了，不改 优/良/中，也不改 `quality_plus/minus`。
3. **不自动合并/删除**：面板只给证据与倾向，删哪本由用户走既有确认流程。

### 1.1 为了守住第 2 条，有一处现状要改

`library.rs` 现在把 `edition_vs_peers` 产出的相对文案（「同书另本插图更多」「同书中有注文，另本没有」…）
**`extend` 进了 `quality_plus/minus`**（`list_library_cached` 末尾那段）。这违反「独立评价」：

- 同一本书，只要库里的同书变了，它的「依据」列表就跟着变——依据不再是这本书自己的属性；
- 三本同书时，「另本」指谁说不清；
- 结论重复：面板与角标悬浮两处说法，容易各自漂移。

**做法**（已实现）：`quality_plus/minus` 只留本书自身的绝对事实；`edition_vs_peers` 的产物改由对照面板呈现。
评级数值本身不变（它从来没把 peers 算进 `good/bad`）。

### F1 — 两本正文逐字一致

把 228 个 XHTML 全部去标签、去空白后逐文件比对：**228/228 完全相同**（连实体写法都一致）。
所以这一对属于下面第 3 节的「同一排版源重打包」——比较只需要回答**包装**问题，不需要比内容。

### F2 — 指纹之所以不同，是因为 XML 声明被当成了正文（bug）

- `27.3 M` 版：228/228 个文档的声明是 `<?xml version="1.0" encoding="utf-8" standalone="no"?>`
- `34.2 M` 版：0/228 个带 `standalone="no"`

`scan_html`（`src-tauri/src/book_signals.rs`）在 `<` 后只处理 `!`（注释/doctype）和 `/`，
然后收集 ASCII 字母做标签名。`<?xml …` 的 `?` 让 `name` 为空，走 `"" => text.push('<')` 分支，
于是**整条处理指令原样进了正文文本**。` standalone="no"` 正好 16 个字符，与实测完全吻合：

- `chapterChars`：**384/384 个单元差额恰好 +16**（`27.3 M` 版更大）
- 每文件原始字节差 17–19，多出来的 1–2 字节是 `<link … />` 与 `<img … />` 的空格，被 `norm_ws` 吃掉了

也就是说：**两本正文完全一致的书，指纹不同、字数不同，只因为一个 XML 声明。**
它们现在能归成「同书」，靠的是弱点的那条兜底规则（`headings` 相同 + 字数差 <2%），而不是精确指纹那条。
（整书 `chars` 差 3285 而不是 384×16，因为 `chars` 按唯一文件去重、`chapterChars` 按 spine 单元计数——
两个口径本来就不一致，对照面板不该把它们混着用。）

### F3 — 5.2 MB 的体积差，全部是封面/推广图，不是内容

`34.2 M` 版是一个**手机版 repack**：把总封面从平板竖版换成手机竖版，并把旧封面和一张 Kindle 推广图
留在包里没删。三张图的账（字节全部核对过）：

| 文件 | 大小 | `27.3 M` 版 | `34.2 M` 版 |
| --- | --- | --- | --- |
| `OEBPS/Images/平板.jpg` | 915 KB | `body.cover-page` 背景（在用） | 只挂在 manifest 里，**成了孤图** |
| `OEBPS/Images/phone.jpg` | 4429 KB | 不存在 | `body.cover-page` 背景（在用，1080×2400） |
| `OEBPS/Images/Kindle.jpg` | 802 KB | 不存在 | 只挂在 manifest 里，**孤图** |

- 两本的 CSS 只差 6 字节：`background-image` 从 `平板.jpg` 换成 `phone.jpg`（注释也跟着改）。
- 两本 `img_count` 都是 35，**正文插图数完全没变**——多出来的两张不是内容。
- `img_bytes` 差额 5,356,160 B = phone.jpg + Kindle.jpg，**分毫不差**。

这套书的封面是 **CSS 背景图**，不是 `<img>`（`body.cover-page` + 内联
`style="background-image:url(../Images/vNN-cover.jpg)"`）。「被引用」不能只看 `<img src>`，
必须连带 CSS 的 `url()` 一起扫——10 张分卷封面全靠这条路径才看得见。

### F4 — 现有对照的阈值太钝，差异全被吃掉

`edition_vs_peers` 判「插图更多」要 `my >= peer + 8` 或 `my >= 2×peer`。46 vs 44 两条都不满足 → 平局 → 无话可说。
其它轴（注文/上标/标识符/乱码/缺字）全是 0 = 0。于是这一对**有真实差异的书，得到的对照是一张白纸**，
而这唯一的真实差异（2 张残留图 / 1.7 MB 垃圾）恰好是决定「留哪本」的那条。

## 3. 先判关系，再选口径

「同一排版源的两次打包」只是同书关系的一种。**同一个面板要处理多种关系，而不同关系该看的轴完全不同**——
所以第一步是分类，不是直接摆数字。分类只用既有信号，两个正交判据：

- **判据 A：正文是否同源** — 逐章 `chapter_shas` 序列比（同源 = 逐章 sha 全等）
- **判据 B：回目集合关系** — `headings`/回目序列相等 / 包含 / 分区 / 无关

| 关系类型 | 判据 | 比较要回答的 | 能判优劣吗 |
| --- | --- | --- | --- |
| **同一排版源重打包** | A 全等 · B 相等 | 只有包装差异：孤图、推广页、体积水分 | 能（打包组） |
| **换设备/渠道打包** | A 全等 · 封面/图集不同 | 同上 + 封面规格（手机竖版 vs 平板竖版） | 能（打包组）——**范本属于这条** |
| **同书异版** | A 有真实差异 · B 相等 | 正文哪版更干净更全；注文/插图装置谁多 | 能（正文 + 装置组） |
| **完整版 vs 删节/选编** | B 包含（子集） | 缺了哪些回目 | 能（完整性压倒其它轴） |
| **分卷 vs 合集** | B 分区（合集 = 分卷并集） | 是不是同一套的两种装订 | 不判优劣，只提示关系 |
| **不同译本/校注本** | B 无关或作者/译者不同 | 不比较内容，只并列元数据与回目 | `Incomparable`，只呈现 |

分类错了，后面全错：把「同源重打包」当异版比，会让 F2 的 XML 声明噪声变成「正文有差」；
把「删节版」当异版比，会用字数判优劣，而删节版字数少未必是缺点。**面板顶部先写关系类型，再谈轴。**

## 4. 对照面板设计

### 4.1 前置修复：先让测量可比较（已实现）

对照建立在 `BookSignals` 上，所以先修测量层，否则面板会把 F2/F3 的噪声当结论：

| 修复 | 做法 | 影响 |
| --- | --- | --- |
| **忽略 XML 处理指令** | `scan_html` 加一条：`?` 时跳到 `?>`（与 `<!doctype` 同款处理） | 正文一致的两本 → 指纹一致，判据 A 才可靠；字数不再虚高 |
| **图三分解** | 扫 spine 文档的 `<img src>` 与全书 CSS（含内联 style）的 `url()`，与 manifest 求交：只被封面页引用 = 封面图；无人引用 = 孤图；其余 = 正文插图 | `Kindle.jpg`（孤图）、`平板.jpg`（被换掉后成孤图）、`phone.jpg`（封面图）分得开 |
| **章级差异分类** | 逐 `chapter_shas` 比较，每章标 `identical` / `boilerplate`（差额恒定且只差声明类噪声）/ `edited` | 判据 A 从「字数 ±2%」升级成逐章实证，能看出差异是均匀还是成片 |
| **体积分解** | 字节拆成 正文 / 正文插图 / 封面 / 孤图 | 直接回答「这本为什么大 5.2 MB」 |

`analysis_kind` 递增以作废旧缓存。

### 4.2 数据模型（Rust 侧）

新增 `src-tauri/src/book_compare.rs`（只读 `BookSignals` + 既有 `Book` 元数据，不碰 zip/OPF，不分派格式）：

```rust
#[serde(rename_all = "camelCase")]
pub struct Comparison {
    pub kind: RelationKind,            // 见 §3 的关系类型
    pub kind_note: String,             // 「同一排版源 + 换设备打包」的依据一句话
    pub columns: Vec<CompareColumn>,   // 文件名 / 显示名 / 角标 / 封面 rev
    pub axes: Vec<CompareAxis>,        // 行
    pub chapter_diff: Option<ChapterDiff>, // 逐章差额（同回目且 2 本时给）
    pub conclusion: Vec<String>,       // 「倾向保留 X」+ 支撑轴
}

#[serde(rename_all = "camelCase")]
pub struct CompareAxis {
    pub key: String,            // "text" | "plates" | "orphan_images" | "payload" | ...
    pub label: String,
    pub group: AxisGroup,       // Content | Apparatus | Packaging
    pub note: Option<String>,   // 怎么量出来的
    pub applies: bool,          // 该关系类型下是否有意义（无意义则整行隐藏）
    pub cells: Vec<CellValue>,
    pub verdict: Verdict,       // Tie | Winner(usize) | Incomparable
}

pub struct CellValue {
    pub display: String,        // "44 张" / "14.4 MB" / "0"
    pub num: Option<f64>,       // 可排序/可画柱的原始值
    pub mark: CellMark,         // Best | Worst | Tie | Only | None
}
```

### 4.3 轴清单

`applies` 按 §3 的关系类型裁剪：同源重打包时「正文」整组只留一行「逐字一致」，不摆没意义的字数。

| 组 | 轴 | 来源 | 适用 | 判优方向 |
| --- | --- | --- | --- | --- |
| 正文 | 逐章差异分类（一致 / 打包噪声 / 真实差异） | `chapter_shas` | 全部 | 只呈现；有真实差异才展开 |
| 正文 | 正文字符数（去空白） | `chars`（修 F2 后） | 异版 | 只呈现，**不判优**（删节版字数少未必差） |
| 正文 | 回目集合关系 | `headings` | 全部 | 相等 / 包含 / 分区 / 无关，各自说明 |
| 正文 | 乱码 · 缺字 · `<br>` 密度 · 空 `<p>` | 既有字段 | 全部 | 少者赢 |
| 装置 | 词注 / 上标注文条数 | `word_notes` / `sup_count` | 全部 | 多者赢（有注文是本项目明说的长处） |
| 装置 | 正文插图数 / 字节（被正文引用，≥20KB） | 新增三分解 | 全部 | 多者赢 |
| 装置 | 插图平均单图字节 | 正文插图字节 / 张数 | 全部 | 只呈现（同张数下更大≈码率更高，见 epub-stable-id） |
| 打包 | 封面图字节 | 新增 | 全部 | 只呈现（封面印成 915 KB 还是 4.4 MB 只是打包选择） |
| 打包 | 孤图数 / 孤图字节 | 新增 | 全部 | **少者赢**（残留噪声，不是长处） |
| 打包 | 体积分解 | 新增 | 全部 | 只呈现，解释「为什么大」 |
| 打包 | 是否同一排版源 | 逐章 sha | 全部 | 前置判据，不是优劣 |
| 溯源 | 标识符等级（ISBN > ASIN > 内部 > UUID > 无） | `id_quality` | 全部 | 高者赢 |
| 溯源 | 元数据完整度（作者 · 出版者 · 日期 · 语言 · 丛书） | `Book` 元数据 | 全部 | 多者赢，逐项列 |

### 4.4 判定规则

- **每轴独立判** `胜 / 负 / 平 / 不可比`，不给加权总分。理由：「注文比插图重要」这类权重没有依据，
  与 v0.10.0 拒绝伪精确分数是同一立场。
- **平局要显示**（「= 44 · 44」），不静默——F4 的坑就是「接近」被吞掉。
- **接近标 ≈**：差额在容差内（插图 ±2 张、字数 ±0.5%）标「≈」，判决仍算平局。容差用比例，不用绝对值。
- **`Incomparable` 要说明原因**：格式不同、`analysis_kind` 不齐或信号缺失时明说，不退化成「= 0 · 0」。
- **结论给倾向**：一行「倾向保留 X」，支撑它的轴可点开。倾向只按轴汇总，**不触发任何删除**。

### 4.5 UI

- **入口**：书架卡片上的「同书 · 另有 N 本」徽标变成按钮 → 打开对照面板；3 本以上先选 2–3 本。
  （阅读顶栏不加入口：比较是书架动作。）
- **形态**：居中面板（与「编辑元数据…」同款浮层），宽屏并排、窄窗纵向堆叠。
- **表格**：行 = 轴（按组），列 = 版本。每格 `值 + ▲/▼/=≈`，`Best` 高亮，`Only`（只有这本有）单独标记。
- **默认只看差异**：平局组折叠成一行「正文装置 5 项一致」；顶栏给「显示全部」勾选。默认视图才是结论。
- **逐章差额**：两本同回目时给一条 384 格细条带（绿=一致／灰=打包噪声／红=真实差异），点击跳章——
  一眼看出差异是均匀的还是成片的。
- **结论条**置顶：关系类型 + 倾向 + 支撑轴。面板内**不提供删除**，只提供「打开这本」/「在书架定位」。

## 5. 独立评价算法的优化建议

**前提：不改 优/良/中 的定义**（`bad == 0 && good >= 3` → 优；`bad == 0 && good >= 2` → 良；否则中），
只改喂进去的**指标口径**。每条都标出是否会让已有角标变化（变则需 bump `analysis_kind` 重算）。

| # | 现状 | 问题（范本例证） | 建议 | 会改已有角标吗 |
| --- | --- | --- | --- | --- |
| 1 | XML 处理指令计入正文 | `chars` 虚高 3285、指纹误判（F2） | ✅ **已修**：`scan_html` 忽略 `<?…?>` | 已生效：两本范本指纹与字数现已相同 |
| 2 | 插图 = manifest 全量 | 封面与残留推广图冒充插图（F5：44/46 张里只有 39 张是内容） | ✅ **已改**：计分改用 `img_referenced_substantial`；封面图、孤图单列 | 本机书库 8 本 EPUB **0 本变档**；理由里的数字 46 → 39（见下） |
| 3 | `img_truncated` 时给 `good += 1` | 图多到扫不完反而算长处，且 `img_bytes`/`img_substantial` 已被截断、不可信 | 截断时相关轴标「未知」，**不给 good** | 会（超 300 张图或 48 MB 的书） |
| 4 | `br_per_k > 12` 一票否决 | 12.1/千字与 40/千字同罚，直接掉出优 | 分两档：>12 记「偏多」提示，>20 才算缺陷（`bad`） | 会（换行偏多的书可能升档） |
| 5 | 长处不分量级：≥8 张插图与 60 张同为 `good+1` | 两本范本理由列表结构完全一样，优内部零分辨率 | 长处分档（≥8 张 / ≥40 张各算一档），**标签仍是三档** | 会（插图多的书可能从良到优） |
| 6 | `empty_p` 采集了但从不使用 | 空 `<p>` 是打包噪声，与「书好不好」无关 | 归入打包组供对照面板用，**不进评级** | 不会 |
| 7 | 字数只进 `plus`，不进 `good` | 其实没评——但对照面板容易误用字数判优劣 | 保持不进评级；完整性改用§3 的回目包含关系判 | 不会 |
| 8 | 缺陷同样不分量级：1 处乱码与 5000 处同罚 | 「有 1 个 `�`」和「满篇乱码」都封顶在良 | 缺陷分档（阈值 + 密度），只影响 `bad` 的分量说明 | 会（视档位设计） |

优先级：#2 与 #1 先做（是 F2/F3 的直接病根，也是对照面板正确性的前提）；#3、#4 是明显的不合理阈值；
#5、#8 动的是评级粒度，**建议先只用在实际重算一次书架时评估影响面再定**。

**#2 的影响面实测**（what-if 把插图轴换成 `img_referenced_substantial` 后重评，只读不写）：

| 书 | 角标 | 较大插图 |
| --- | --- | --- |
| 27.3 M 王立群读史记套装 | 优 → 优 | 44 → 39 |
| 34.2 M 王立群读史记套装 | 优 → 优 | 46 → 39 |
| C-028 史记 | 优 → 优 | 247 → 246 |
| 真实案件才更瘆人 | 良 → 良 | 2 → 2 |

**8 本 EPUB（4 种书）里 0 本变档。** 原因：门槛是 8 张，换口径后仍然够（39 ≥ 8）；
而《真实案件》本来就低于门槛，没吃到这个长处。改动落地后复测确认：角标一本未动，
理由里的数字变成了「较大插图 **39** 张（≥20KB，正文引用，不含封面/包内未引用的图）」。

**旧缓存不迁移**：`analysis_kind < 3` 的条目仍按旧口径（manifest 全量）评分，
所以升级后书架上不会有一本书在重新打开之前变档；重开即自动切到新口径。

样本只有 4 种书，换一批书——尤其是"图多但其实全是封面/推广图"的——仍会出现降档，那正是本次要纠正的情形。

1. **别拿裸 `cargo build` 的 exe 去截图**。debug exe 里确实嵌了 bundle，但也带着 `devUrl`，

## 10. 待定

- **PDF 是否参与对照**：一期只让 EPUB 进面板（PDF 的 `BookSignals.pdf` 是另一套语义，混排会产出
  「0 字符」这类废话——`library.rs` 里已有 `if this.pdf.is_some() { continue }` 的先例）。
- **同名 `.epub` 与 `.pdf`**：AGENTS 明确「扩展名是身份的一部分」，是两本书，不参与同书对照。
- **§5 的 #5 / #8（评级粒度）**：要不要动、怎么分档，需先评估对现有书库角标的影响面再定。
- **逐章条带**目前只读展示；点击跳章需要开书 + 落 locator，留待下一步。
- **面板里没有封面缩略图**：列头用书名 + 文件名 + 角标 + 体积识别。要加的话得把 `coverUrl`
  与占位图重试逻辑从 `Library.tsx` 抽成共享模块，别抄一份。
- **`edition_vs_peers` 的去留**：面板已由 `book_compare` 接管轴判定；这个旧函数只剩单测在用，
