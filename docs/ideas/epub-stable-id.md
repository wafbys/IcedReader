# 想法：EPUB 稳定标识与书库质量分（已实现，随 v0.8.0 发布）

状态：三个边界已定稿（2026-09-04）并已实现；功能已随 v0.8.0（2026-09-04）发布——书架质量分级（优/良/中 角标 + 依据浮层 + 未读排序）与同书提示（重打包 / 同书异版只提示不合并），见 `docs/releases/v0.8.0.md`。三个边界不变：
1. 命中同书只**提示**，不自动合并/删除；
2. 书架**排序掺入质量分**，封面左上角显示 优/良/中；
3. 计算在**首次导入**时进行（不进 list 热路径），导入过程有 UI 反馈（书架「正在导入并分析…」）。

实现位置：`src-tauri/src/book_signals.rs`（正文指纹 + 质量信号 + 评级与缓存 `data/book-signals.json`）、`library.rs`（`quality`/`duplicates` 填充与排序）、`open_book`（首次分析）、书架 UI（角标/同书提示/分析反馈）。AGENTS 书架与绿软段已同步。后续若调整阈值/信号在实现内改即可。

## 背景

- 同一本书常有多份 epub（不同站点 / 工具反复重打包），文件名、`dc:identifier`、封面、字体、哈希都会变。
- 用户想用「组合方式」尽可能探测一本 epub 的**稳定标识**，用于（候选用途）识别重复、重打包后保留进度/划线。
- `scripts/epub-id.py` 是早期实验（dc:identifier → 全内容哈希 → size+mtime），问题已知，尚未定方案。

## 待定问题（已定稿）

1. 主要用途：**书库内提示同书 + 质量分参与排序/封面展示**（不做自动合并，不做外部查重工具）。
2. 「同一本」容忍度：正文指纹一致 = 同排版源（重打包）；回目序列一致 + 字数带 = 同书异版。**命中只提示，删除由用户确认**（沿用现有删书确认流程）。
3. 成本门槛：**首次导入**算正文指纹与质量信号并缓存（data/），list_library 只读缓存；导入分析需 UI 反馈（进行中提示）。
4. 方案倾向（已随定稿收敛）：
   - 输出「候选 id 集合 + 来源/置信度」用于提示文案，质量分用低/中/高 + 理由列表（不追求伪精确分数）。
   - `dc:identifier` 按形态分级（isbn/url 可信；`urn:uuid` 多为每次重打生成，不可信）。
   - 更稳的信号是「按 spine 顺序的正文文本指纹（去空白、含章数）」。
   - 计算放 Rust（zip/rbook 已有），python 脚本仅作开发期对照；质量/指纹缓存键=文件 rev。
5. 若定稿会动书架去重/进度语义，需同步 AGENTS（现「不做内容哈希去重，除非产品明确要求」）。

## 已演示的对比口径（在两本东周列国志上验证过，勿直接实现）

- **判同一排版源**：按 spine 顺序对每个章节文档做「去标签、去空白正文」的 sha；两序列以相同 sha 为锚对齐（文件名可能整体错位一拍——A 多目录页时 partNNN 全会平移）。同源重打包会逐文件同 sha。
- **判同书异版**：回目序列一致 + 总字数 ±2% + 语言一致。
- **质量信号**：乱码 `�`、未闭合标签残留（坏 `<img` 会漏成可见杂字）、`<br>` 密度、图片字节/张数（同张数下体积高≈码率高）、identifier 形态（isbn 可溯源 > asin > 随机 uuid）。
- 实测结论示例：两本东周列国志正文逐文件一致，差异只有「书内目录页有无」与两处坏 HTML 图标签残留；带 ISBN 的本（黄钧校注/9787020058716）图像码率更高、无坏标签，判定为更优。
